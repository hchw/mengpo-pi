# Mengpo Pi · 记忆适配器

把 [Mengpo](https://github.com/hchw/mengpo) 记忆服务接到 [pi](https://github.com/earendil-works/pi) 编码智能体上的扩展，让 pi 在会话中拥有跨会话、可治理、可追溯的长期记忆。

## 背景

pi 每次新会话都从零开始：项目约定、踩过的坑、上次为什么那样改、用户反复纠正过什么——这些经验要么留在人的脑子里，要么散落在仓库与历史会话里，既不会被检索，也不会跨会话累积。

Mengpo 是一个独立的记忆服务：租户级物理隔离、治理状态机、证据与置信度、可解释的混合召回与投影预算。本扩展负责把 pi 接上去。

pi 不是"主流聊天 Agent"，而是编码智能体：它原生带有工具调用标识、会话条目的树形结构、重试与测试结果。因此它以 **Level 2 深度 Runtime Adapter** 的方式接入——不只是旁观消息，而是把「哪次投影、用了哪些记忆、哪次工具调用、哪个结局」串成一条可归因的链路，让失败归因达到直接归因精度。

## 功能

> 规划已完成，实现进行中。以下为计划提供的能力。

- **按场景触发召回**：在新用户输入、任务切换、连续失败、用户显式要求回顾时召回并注入；纯工具循环与无新证据的追问则跳过，避免提示缓存前缀反复失效。判定失败退回"按轮召回"这一安全默认。
- **会话活动上报**：工具调用与结果、助手回复、轮次结局，均以显式的来源类别与事件类型上报，而不是把语义塞进载荷字段。
- **Level 2 运行时 trace**：从 pi 原生的工具调用标识与会话条目树推导任务、尝试、投影、工具结果与结局标识；缺失即省略，不填占位值。
- **记忆工具与人工命令**：向模型提供按查询召回、记住、忘记、纠正；向用户提供 `/memory` 查看接入状态与本轮注入情况。
- **反馈回传**：用户的纠正与显式反馈关联到对应记忆。
- **降级可用**：任何一次调用失败都静默降级为"无记忆"；未配置接入时不发起任何调用；已配置但不可用时降级并熔断。记忆功能不会阻塞会话，也不会成为对话延迟的来源。

## 使用方法

> 尚未发布，安装与配置方式将随首个版本补全。

前置依赖：需要 Mengpo 侧的 `memory-level2-ingress` 变更**先行发布**。Mengpo 的请求解码为严格模式，未知字段会被拒绝（`INVALID_ENVELOPE`，400），因此扩展与服务端不能各自独立升级。
